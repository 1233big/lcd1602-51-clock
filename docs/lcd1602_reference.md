# LCD1602 参考手册

配套 `lcd1602.c` / `lcd1602.h` / `main.c`，目标芯片 AT89C52 / STC89C52，12 MHz 或 11.0592 MHz。

本手册回答四个问题：接线与时序是什么、每条指令什么意思、C 代码在总线上到底发出了什么、延时和定时器初值是怎么算出来的。

同目录的 `lcd1602_demo.asm` 是同一套逻辑的完整汇编源码（Keil 可直接打开重编），对照本手册阅读。

## 1. 接线

| LCD1602 引脚 | 接到 | 说明 |
|---|---|---|
| VSS | GND | |
| VDD | +5V | |
| V0 | 电位器中间脚 | 对比度，偏高偏低都会看不见字 |
| RS | P2.6 | 0 = 写指令，1 = 写数据 |
| RW | P2.5 | 0 = 写，1 = 读（本项目只写不读） |
| E | P2.7 | 下降沿把总线锁进 LCD |
| D0 ~ D7 | P0.0 ~ P0.7 | 8 位数据总线，P0 开漏需上拉 |
| A / K | 背光正 / 负 | |

P2.5 ~ P2.7 在常见开发板上同时接 LED6 ~ LED8，写屏时这三颗灯会闪，属于电气共用，不是程序错误。

## 2. E 脚时序

```
RS/RW  ______________| 数据在这里必须已稳定
D0~D7  ==============|XXXXXXXXXXXXX   写入的值
E      __________|~~~~|____________  高电平 >= 450 ns，下降沿锁存
                  ^    ^
                  |    +-- 数据保持 >= 10 ns
                  +------- 数据建立 >= 80 ns
```

HD44780 标准值：

| 参数 | 要求 |
|---|---|
| E 高电平脉宽 | ≥ 450 ns |
| 数据建立时间 | ≥ 80 ns |
| 数据保持时间 | ≥ 10 ns |
| 普通指令执行 | ≤ 37 µs |
| 清屏 / 归位 | ≤ 1.52 ms |

结论：只要保证 E 拉高后至少停留 450 ns、每条指令后至少等 37 µs，MCU 再慢也不会写错。本项目用 5 µs 和 40 µs，留有余量。

## 3. 指令集（只有本项目用到的）

| 指令 | 二进制 | 作用 |
|---|---|---|
| `0x38` | 0011 1000 | 功能设置：8 位数据口（DL=1）、两行（N=1）、5×8 点阵（F=0） |
| `0x0C` | 0000 1100 | 显示开关：显示开（D=1）、无光标（C=0）、不闪烁（B=0） |
| `0x01` | 0000 0001 | 清屏并回原点，执行时间 1.52 ms |
| `0x06` | 0000 0110 | 输入模式：光标右移（I/D=1）、整屏不滚动（S=0） |
| `0x80 \| addr` | 1000 AAAA | 设置 DDRAM 地址，即光标定位 |

写字符不是指令：RS=1 时发一个 ASCII 码即可，例如 `'5'` = `0x35`。

## 4. DDRAM 地址

- 第一行：`0x00` ~ `0x27`，实际可见 `0x00` ~ `0x0F`（16 列）
- 第二行：`0x40` ~ `0x67`，实际可见 `0x40` ~ `0x4F`（16 列）

`LCD_SetCursor(row, col)` 的换算：

```c
addr = (row == 0) ? col : (0x40 + col);
LCD_WriteCmd(0x80 | addr);
```

例：第二行第 7 列 → `0x40 + 6 = 0x46` → 发 `0xC6`。

地址不会自动换行。第一行写到 `0x0F` 之后会进入 `0x10` ~ `0x27` 这段不可见 DDRAM，屏幕上表现为字符消失。整行写完要手动重新定位。

## 5. C 代码对应的汇编

### 5.1 写指令 `LCD_WriteCmd(cmd)`

```c
LCD_RS = 0; LCD_RW = 0; LCD_DATA = cmd;
LCD_E = 1; LCD_Delay5us(); LCD_E = 0; LCD_Delay40us();
```

```asm
CLR   P2.6        ; RS = 0，本次是命令
CLR   P2.5        ; RW = 0，写方向
MOV   P0, A       ; 命令字节上总线
SETB  P2.7        ; E 拉高，LCD 开始采样
LCALL DLY5        ; 保持 >= 450ns，这里给 5us
CLR   P2.7        ; E 下降沿，LCD 锁存总线
LCALL DLY40       ; 等指令执行完，普通指令 <= 37us
```

### 5.2 写数据 `LCD_WriteData(dat)`

序列完全相同，只有第一行不同：

```asm
SETB  P2.6        ; RS = 1，本次是显示数据
```

### 5.3 字符串 `LCD_WriteString(str)`

`while (*str)` 循环在汇编里就是一个指针循环：

```asm
MOV   DPTR, #STR
LOOP:
MOVC  A, @A+DPTR      ; 取一个字符
JZ    DONE            ; 遇到 '\0' 结束
SETB  P2.6
CLR   P2.5
MOV   P0, A
SETB  P2.7
LCALL DLY5
CLR   P2.7
LCALL DLY40
INC   DPTR
SJMP  LOOP
DONE:
RET
```

### 5.4 定宽数字 `LCD_WriteNumAt(row, col, num, width)`

用整数除法从高位取位：

```
div = 10^(width-1)
循环 width 次:
    digit = (num / div) % 10
    发 '0' + digit
    div = div / 10
```

例：`num=7, width=2` → `div=10` → 发 `'0'`、`'7'` → 屏幕显示 `07`。时钟能显示 `07:05:09` 而不是 `7:5:9` 靠的就是这里。

## 6. 延时是怎么定的

12 MHz 晶振、标准 12T 8051：1 个机器周期 = 12 / 12 MHz = 1 µs。

| 函数 | 实现 | 实际时长 | 用途 |
|---|---|---|---|
| `LCD_Delay5us` | `volatile unsigned char i = 2; while (i--);` | 约 5 µs | E 高电平保持，要求 ≥ 450 ns |
| `LCD_Delay40us` | 同样空循环，参数 18 | 约 40 µs | 指令执行等待，要求 ≥ 37 µs |
| `DelayMs` | 双层循环，内层 110 次 | 约 1 ms/单位 | 上电 40 ms、清屏 2 ms 等粗等待 |

这些数不需要精确：它们只负责「不能太短」，长一点没有副作用。

为什么不用忙标志判断：HD44780 支持读 BF（D7）判断忙，但需要把 P0 先置 1、再切 RW 读取。本项目只写不读，用固定延时更简单，代价是每次写屏最多多等 40 µs；在 16×2 小屏上可以忽略。

## 7. 初始化流程

`LCD_Init()` 的实际顺序：

| 步骤 | 动作 | 等待 |
|---|---|---|
| 1 | `E=0, RS=0, RW=0, P0=0xFF`，先让总线处于确定状态 | — |
| 2 | 等 LCD 内部上电复位（数据手册要求 ≥ 15 ms） | 40 ms |
| 3 | 发 `0x38` 功能设置：8 位、两行 | 2 ms |
| 4 | 再发一次 `0x38`，防止上电时总线不稳错过第一条 | 2 ms |
| 5 | 发 `0x0C` 开显示、关光标、关闪烁 | 2 ms |
| 6 | 发 `0x01` 清屏（要求 1.52 ms） | 2 ms |
| 7 | 发 `0x06` 输入模式：光标右移 | 2 ms |

严格按数据手册，8 位模式的唤醒序列是：

```
等 15ms → 发 0x30 → 等 4.1ms → 发 0x30 → 等 100us → 发 0x30 → 再发 0x38
```

这是为了兼容「上电时 LCD 可能还在 4 位模式」。本项目省掉前两次 `0x30`，直接发 `0x38`：绝大多数 1602 模块上电即为 8 位模式，实测可用。若遇到上电偶发乱码或只显示方块，先把这两步补回去再排查其他原因。

## 8. 定时器初值

目标：每 1 ms 中断一次。

```
12 MHz            → 1 机器周期 = 1 µs
1 ms              → 1000 个机器周期
方式 1 是 16 位加计数，溢出值 65536
初值 = 65536 - 1000 = 64536 = 0xFC18
所以 TH0 = 0xFC，TL0 = 0x18
```

计时链：定时器每 1 ms 溢出 → 进中断 → `flag++` → `flag` 到 1000 时 `sec++` 并清零，即 1000 × 1 ms = 1 s。

**换成 11.0592 MHz 会怎样**：1 机器周期 = 12 / 11.0592 ≈ 1.085 µs，1000 个周期 = 1.085 ms，比 1 ms 长 8.5%，时钟每天慢约 2 小时。要修正就把初值改成 `65536 - 1000 × (12 / 11.0592) = 65536 - 921 = 0xFC67`（`TH0=0xFC, TL0=0x67`），或者把 `flag` 的阈值从 1000 改成 922。

为什么中断里要重装初值：方式 1 不会自动重装，不重装就会从 0 开始计数，周期变成 65536 µs。方式 2 是 8 位自动重装，但最大只有 256 µs，反而需要更多次中断。

## 9. 常见现象对照

| 现象 | 可能原因 |
|---|---|
| 全屏方块 / 一排黑块 | 初始化没成功：延时不够、E 时序错、上电太早 |
| 有背光但无字符 | 对比度 V0 没调好（最常见），或 RS/RW 接反 |
| 只有第一行有字 | 第二行地址算错（应为 `0x40 + col`），或屏本身是 1601 |
| 字符位置错乱 | 写完 16 列没重新定位，字符跑进不可见 DDRAM |
| 显示闪烁 | 刷新频率过高，或没关闪烁光标 |
| 时间走得慢 / 快 | 晶振频率和初值不匹配，见第 8 节 |
| 写屏时 LED6 ~ LED8 闪 | P2.5 ~ P2.7 与 LED 共用引脚，正常现象 |
| 上电偶发乱码 | 8 位唤醒序列不完整，见第 7 节末尾 |
